🎯 PROPÓSITO DEL PROMPT

Queremos transformar un documento `.docx` que contiene un cuestionario de encuesta (ya sea en lenguaje natural o semi-estructurado) en un archivo `.json` que siga una estructura clara, organizada y útil para análisis de datos.

El resultado debe permitir automatizar tareas como simulación de respuestas, análisis estadístico, dashboards o entrenamiento de modelos.

---

💬 PROMPT PARA CONVERSIÓN DOCX → JSON

Eres un asistente experto en análisis de encuestas y estructuración de datos. 

Recibirás un cuestionario para una encuesta aplicado a personas, en formato texto (generalmente extraído desde un archivo `.docx`). Tu tarea es transformar ese contenido en un archivo `.json` estructurado, de acuerdo con las siguientes reglas:

---

🔧 ESTRUCTURA ESPERADA DEL JSON

{
  "tabla": "nombre_tabla_snake_case",
  "descripcion": "Cada fila representa un encuestado. Cada columna representa una variable (pregunta o metadato).",
  "campos": [
    {
      "bloque": "Nombre del bloque o sección temática",
      "variables": [
        {
          "nombre": "Nombre técnico de la variable en camelCase o snake_case",
          "tipo": "String",
          "descripcion": "Descripción de lo que se mide. Debe incluir tipo: RU (respuesta única), RM (respuesta múltiple), RA (respuesta abierta)",
          "opciones": [
            "Opción 1",
            "Opción 2",
            "Opción 3"
          ],
          "nota": "Si se selecciona "Otro", se debe contestar con una respuesta abierta coherente con la pregunta."
        }
      ]
    }
  ],
  "notas_tecnicas": {
    "RU": "Respuesta única: el encuestado debe elegir solo una opción.",
    "RM": "Respuesta múltiple: el encuestado puede seleccionar más de una opción.",
    "RA": "Respuesta abierta: se permite una respuesta libre.",
    "Otro": "Si una pregunta incluye 'Otro', debe agregarse una nota que indique que se espera una respuesta coherente si se selecciona esa opción."
  }
}

---

🧩 DETALLES QUE DEBES DETECTAR EN EL TEXTO

1. Bloques: Si el documento agrupa preguntas bajo títulos como “Bloque A: Contexto económico” o “Parte 1: Información personal”, usa eso como `bloque`.

2. Variables/Preguntas:
   - Usa el texto principal de la pregunta como base del campo `"nombre"` (convertido a camelCase o snake_case si lo automatizas).
   - Si hay un código de pregunta como “A1”, inclúyelo como prefijo: `A1_situacionLaboral`.

3. Opciones:
   - Si la pregunta tiene opciones de respuesta (tipo múltiple o única), agrégalas al campo `"opciones"` exactamente como aparecen.
   - Si aparece algo como “Otro: ________”, agrega una `"nota"` explicando que debe escribirse algo coherente.

4. Tipo:
   - Usa `"String"` para todas las respuestas.
   - Indica en el campo `"descripcion"` si es:
       - RU: Respuesta única
       - RM: Respuesta múltiple (puede tener varias respuestas)
       - RA: Respuesta abierta

5. Casos especiales:
   - Si el cuestionario incluye instrucciones como “responda con una escala del 0 al 10”, indícalo en `"descripcion"`, pero deja `"tipo": "String"` o `"Integer"` si corresponde.
   - Si hay campos que no tienen opciones visibles, trata de deducir si son abiertos (RA).

---

🛑 RESTRICCIONES

- No devuelvas explicaciones.
- No incluyas texto adicional fuera del JSON.
- Si hay información ambigua, marca el campo `"nota"` para indicar que requiere validación.
- Usa codificación UTF-8 y asegúrate de que los acentos y caracteres especiales se mantengan.
